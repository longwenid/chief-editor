# 流程 C：立项提案（三通道）

进入条件：用户要开新书、或说"找个方向"、或唤醒后发现没有 active 项目而用户想推进新书。

前置：读 `references/editorial-judgment.md`；新 market_snapshot 按 `observations[].at` 读取实际观察时间，旧版月度 Markdown 才按 `scan_date`。用于本次判断的 claim 要依据其 evidence_ids 核对当月/陈旧，不能用 created_at 或保存文件名替代；具体口径见 `flows/market.md` 记忆小节。有 `teardowns` 更好。写决策前对一遍 `memory/templates.md` §3。市场、商业判断、作品价值、作者偏好分开呈现；没有细读或作者原话时明确未知。

## C0 判通道（开新书第一步）

判定结果写进 decisions 的 `selection_mode`。

| 情形 | 通道 | 做法 |
|---|---|---|
| 用户本次给了想法 | **A 用户想法** | 压力测试后保留用户明确核心；已要求据此开书时，自主补全范围内的内容 |
| 没想法，但本次用户原话或 `authorization.md` 头部有仍有效、且覆盖本次新书选题的委托（逐条核对范围与撤销记录） | **B 总编自决** | 本次新委托先入台账，在该范围内直接形成唯一主见，不再询问 |
| 没想法也没委托 | **一次性提问** | 给想法即 A、让总编定即 B、要多案即 C；同一本书不重复追问 |

用户明确把本次开书交给总编时，总编对完整开书方案及其修正负责：在原话覆盖的范围内补全内容、作出取舍并推进十三门，不把每个空缺重新交还用户。授权范围与恢复按 `policy.md`；记录中区分用户明确约束与总编自定项。自定项发现问题时按真实回退流程修正，只有触及用户明确约束、保留决定权或超出委托范围时才取缺失决定。

## C1 方向查重（三通道共同，候选生成前与落定前各过一遍）

方向 = **类目 ＋ 核心脑洞**（例：力量计税 = 仙侠修真 × 计税制度；神明维修工 = 都市异能 × 神话残骸维修）。核心脑洞也可由人物困境或关系冲突概括，不要求每本书都有超常设定或新规则；该指纹用于项目查重，不充当作品价值标准。先按 `memory/templates.md` 的“当前方向同步”核对已完成方向变更是否投影，再对照 `$CHIEF_EDITOR_MEMORY/decisions/` 里全部 `status: active` 条目的当前方向指纹；旧候选描述不覆盖新投影，未同步或尚在重选的方向明确标示不确定性：

- **类目与核心脑洞双同 = 撞向，必须换方向**；
- 只同其一不算撞向，在差异增量声明里说清增量即可；
- 既有条目没有方向指纹字段时从其 `chosen` 与门选择提炼，不回溯改写原条目；
- 对照面只有方向指纹与状态摘要，不读其他项目的正文与设定（`references/red-lines.md#12`）。

按通道处置：

- **通道 B**：绕开全部已占方向后形成唯一主见——类目或核心脑洞至少其一不与任何 active 项目相同；
- **通道 C**：候选生成时直接排除撞向候选（"同结构异实现"不豁免双同）；
- **通道 A**：用户想法撞向时点破（指明与哪个项目撞、撞在哪一维）并给换向建议；用户仍坚持则按作者决定权留痕放行，decisions 注明撞向对象与坚持原话。

## C-A 用户想法（保留用户核心，自主补全范围内内容）

逐项做诚实压力测试：

1. **差异化**：与快照/拆解里同方向在位书相比，增量是什么（无增量就明说）；
2. **市场对位**：快照的 `crossover` 与 `volume_benchmarks` 里有没有它的读者盘与体量档；
3. **原创红线**：`flows/teardown.md` 三条红线逐条自查；
4. **方向查重**：按 C1 通道 A 处置。

结论如实呈报——可行说可行，有硬伤就点破并给替代形状。用户已要求据此开书时，在其明确核心与禁区内自主决定未指定的人物、关系、视角、节奏和其他开书内容，并说明它们怎样支撑核心体验。改变用户明确指定的题材、规则或主角处境，按 `policy.md` 核对是否已有覆盖该改变的委托；缺少覆盖才取新决定。不要把总编自行补出的设定当成用户亲定。快照超过一个月先跑 `flows/market.md`。

## C-B 总编自决（唯一主见，不骑墙）

从最新可比证据与拆解形成一个主推方向，不搞 2~3 案并列上交；对内保留最接近的舍弃方向与取舍，避免只有成功理由而没有比较。主见须自答三问：

- 为什么是它（想让什么读者获得什么体验，市场与文本证据各支持到哪里）；
- 它提供什么可辨识的创作增量，为什么值得为它付出相应代价；
- 这份增量怎样持续产生选择、变化与兑现，足以支撑建议体量。

创作增量可以来自规则，也可以来自人物困境、关系结构、叙述视角与声音、具体生活经验等；按本书的类型与阅读目标选择真正关键的判断依据，不要求逐项齐全。已有类型规则可以沿用，新增设定也不自动构成增量。具体比较方式见 `references/editorial-judgment.md`。

理由写进 decisions。随后的十三门 T0 入口按 `policy.md` §3 代选纪律执行：`--source` 逐字记委托原话（常设或逐次）＋当次代选对象与理由，台账记 `decision_kind=delegated`。作者可随时 `back` / `regroup` / `feedback` 纠偏。

## C3 判断与预测（三通道共同）

用 `selection_decision` 证据记录分别写：

- **市场证据与商业适配**：哪些可比观察支持什么读者盘/阶段判断，哪些只是推断；曝光、作者既有读者与样本偏差怎样限制结论。
- **作品价值**：想实现什么具体阅读体验，本类型为什么适用这项比较，创作增量通过什么机制成立，代价与长篇支撑是什么；有文本比较则引用，尚未写出的效果标为假设，不能借热度判为已证实。
- **作者偏好**：只收已表达的原话及对话定位；“没说”写 unknown，不从榜单、委托代选或主流题材推定作者喜欢什么。
- **取舍与改主见条件**：三者冲突时明说。用户明确的核心概念与禁区优先；总编自提方案没有实质增量或反例推翻原理由时，在委托范围内主动修正并重选。只有改变用户约束或超出委托范围才取新决定；不能把“有品位”当自证，也不把自己的先前决定冒充不可变的作者要求。

落定门槛补一条硬标准：每个方向过 `references/editorial-judgment.md` 的**反俗套三查**（俗套命中自审、化石组合负面清单、百本读者测试），结论写入证据块取舍栏；市场快照按"定下限不定上限"使用。

落定前预登记少量可反证预测：判断内容、证据依据、何时/观察到什么算不支持、最低观察条件。保留当时的候选和落选理由；后续复盘引用原记录，不能回写阈值或把预测改成已经发生的故事。数据不足时暂缓商业结论，创作项目仍可按作者明确意愿推进。

## C-C 多案拍板（保留的现行流程）

由快照 + 拆解生成 2~3 个围绕本次阅读目标、可比较且实质不同的候选，不要求它们共享同一套结构；生成时按 C1 排除撞向候选。每案必附：

- 差异增量声明：相对已知同类作品，本案提供什么可辨识且可持续兑现的创作增量，如何形成具体阅读体验、承担什么代价；只有标签替换、没有实质增量的候选不提出；
- 体量档位建议（引用快照 `volume_benchmarks`；市场数据只作选题信号与档位参考，不写成正文目标、不得说成质量结论）。

连同快照结论呈用户拍板（不拍板不立项）。

## C4 落定收尾（三通道共同）

- 在 `$PROJECT` 选定**独立项目目录**（不覆盖已有项目，不建在技能目录或记忆根内）；
- 选完设定 ≠ 正文授权：正文授权属 novel-ledger 的写作阶段，总编在十三门完成后按 `flows/handoff.md` 交接，不取正文授权；
- 写 decisions 条目，登记方向指纹。
- 校验该条单一 JSON 证据块；将记录 ID 与读者承诺、审美取舍摘要带入开书背景，不伪装成作者已确认的约定字段。

## C5 记忆

写 `$CHIEF_EDITOR_MEMORY/decisions/YYYY-MM-DD-<slug>.md`，骨架见 `memory/templates.md` §3：

- `selection_mode`：A / B / C；
- `direction_fingerprint`：`<类目>×<核心脑洞>`；
- `candidates`：全部实际考虑的候选与各自差异增量声明；通道 B 对外唯一主推，对内保留最接近的舍弃方向与取舍；
- `chosen`：选定项；
- `author_quote`：A = 用户想法原话；B = 委托原话＋当次代选理由（理由另起一行，原话不动）；C = 拍板原话；
- `project_path`、`status: active`；
- 通道 A 撞向放行时另注明撞向对象与用户坚持原话。

## 出口

立项落定 → `flows/opening.md` 开书十三门。
