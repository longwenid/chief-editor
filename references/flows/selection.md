# 流程 C：立项提案（三通道）

进入条件：用户要开新书、或说"找个方向"、或唤醒后发现没有 active 项目而用户想推进新书。

前置：读 `references/editorial-judgment.md`；新 market_snapshot 按 `observations[].at` 读取实际观察时间，旧版月度 Markdown 才按 `scan_date`。用于本次判断的 claim 要依据其 evidence_ids 核对当月/陈旧，不能用 created_at 或保存文件名替代；具体口径见 `flows/market.md` 记忆小节。有 `teardowns` 更好。写决策前对一遍 `memory/templates.md` §3。市场、商业判断、作品价值、作者偏好分开呈现；没有细读或作者原话时明确未知。

## C0 判通道（开新书第一步）

判定结果写进 decisions 的 `selection_mode`。

| 情形 | 通道 | 做法 |
|---|---|---|
| 用户本次给了想法 | **A 用户想法** | 压力测试后采用用户核心概念 |
| 没想法，但 `authorization.md` 头部有仍有效、且覆盖本次新书选题的委托原话（逐条核对范围与撤销记录） | **B 总编自决** | 在该范围内直接形成唯一主见，不再询问 |
| 没想法也没委托 | **一次性提问** | 给想法即 A、让总编定即 B、要多案即 C；同一本书不重复追问 |

## C1 方向查重（三通道共同，候选生成前与落定前各过一遍）

方向 = **类目 ＋ 核心脑洞**（例：力量计税 = 仙侠修真 × 计税制度；神明维修工 = 都市异能 × 神话残骸维修）。对照 `$CHIEF_EDITOR_MEMORY/decisions/` 里全部 `status: active` 条目的方向指纹：

- **类目与核心脑洞双同 = 撞向，必须换方向**；
- 只同其一不算撞向，在差异增量声明里说清增量即可；
- 既有条目没有方向指纹字段时从其 `chosen` 与门选择提炼，不回溯改写原条目；
- 对照面只有方向指纹与状态摘要，不读其他项目的正文与设定（`references/red-lines.md#12`）。

按通道处置：

- **通道 B**：绕开全部已占方向后形成唯一主见——类目或核心脑洞至少其一不与任何 active 项目相同；
- **通道 C**：候选生成时直接排除撞向候选（"同结构异实现"不豁免双同）；
- **通道 A**：用户想法撞向时点破（指明与哪个项目撞、撞在哪一维）并给换向建议；用户仍坚持则按作者决定权留痕放行，decisions 注明撞向对象与坚持原话。

## C-A 用户想法（核心概念用户优先，打磨不越权）

逐项做诚实压力测试：

1. **差异化**：与快照/拆解里同方向在位书相比，增量是什么（无增量就明说）；
2. **市场对位**：快照的 `crossover` 与 `volume_benchmarks` 里有没有它的读者盘与体量档；
3. **原创红线**：`flows/teardown.md` 三条红线逐条自查；
4. **方向查重**：按 C1 通道 A 处置。

结论如实呈报——可行说可行，有硬伤就点破并给替代形状。改核心概念（题材、根规则、主角处境）必须用户点头；总编只打磨表达与结构。快照超过一个月先跑 `flows/market.md`。

## C-B 总编自决（唯一主见，不骑墙）

从最新可比证据与拆解形成一个主推方向，不搞 2~3 案并列上交；对内保留最接近的舍弃方向与取舍，避免只有成功理由而没有比较。主见须自答三问：

- 为什么是它（市场证据引用）；
- 它加什么新根规则（差异增量声明）；
- 凭什么跑完（体量档与兑现路径）。

理由写进 decisions。随后的十三门 T0 入口按 `policy.md` §3 代选纪律执行：`--source` 逐字记委托原话（常设或逐次）＋当次代选对象与理由，台账记 `decision_kind=delegated`。作者可随时 `back` / `regroup` / `feedback` 纠偏。

## C3 判断与预测（三通道共同）

用 `selection_decision` 证据记录分别写：

- **市场证据与商业适配**：哪些可比观察支持什么读者盘/阶段判断，哪些只是推断；曝光、作者既有读者与样本偏差怎样限制结论。
- **作品价值**：想实现什么具体阅读体验，文本比较支持什么机制，独特性与成立代价是什么；尚未写出的效果标为假设，不能借热度判为已证实。
- **作者偏好**：只收已表达的原话及对话定位；“没说”写 unknown，不从榜单、委托代选或主流题材推定作者喜欢什么。
- **取舍与改主见条件**：三者冲突时明说。用户确认的核心概念优先；总编自提方案没有实质增量、反例推翻市场理由或违反已表达偏好时，重提或暂停，不能把“有品位”当自证。

落定前预登记少量可反证预测：判断内容、证据依据、何时/观察到什么算不支持、最低观察条件。保留当时的候选和落选理由；后续复盘引用原记录，不能回写阈值或把预测改成已经发生的故事。数据不足时暂缓商业结论，创作项目仍可按作者明确意愿推进。

## C-C 多案拍板（保留的现行流程）

由快照 + 拆解生成 2~3 个**同结构异实现**候选，生成时按 C1 排除撞向候选。每案必附：

- 差异增量声明："对标组合已被市场拥有，本书在其上加什么新根规则"——无增量的候选不提出；
- 体量档位建议（引用快照 `volume_benchmarks`；市场数据只作选题信号与档位参考，不写成正文目标、不得说成质量结论）。

连同快照结论呈用户拍板（不拍板不立项）。

## C4 落定收尾（三通道共同）

- 在 `$PROJECT` 选定**独立项目目录**（不覆盖已有项目，不建在技能目录或记忆根内）；
- 选完设定 ≠ 正文授权：正文还要单独取授权（`flows/writing.md`）；
- 写 decisions 条目，登记方向指纹。
- 校验该条单一 JSON 证据块；将记录 ID 与读者承诺、审美取舍摘要带入开书背景，不伪装成作者已确认的约定字段。

## C5 记忆

写 `$CHIEF_EDITOR_MEMORY/decisions/YYYY-MM-DD-<slug>.md`，骨架见 `memory/templates.md` §3：

- `selection_mode`：A / B / C；
- `direction_fingerprint`：`<类目>×<核心脑洞>`；
- `candidates`：全部候选与各自差异增量声明（通道 B 只有一条主见也按候选格式留档）；
- `chosen`：选定项；
- `author_quote`：A = 用户想法原话；B = 委托原话＋当次代选理由（理由另起一行，原话不动）；C = 拍板原话；
- `project_path`、`status: active`；
- 通道 A 撞向放行时另注明撞向对象与用户坚持原话。

## 出口

立项落定 → `flows/opening.md` 开书十三门。
