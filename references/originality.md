# 相似但原创：对标拆解与选题边界

何时读：从市场快照选拆解对象时、执行拆解时、生成立项候选时、开书自执 premise/world 门之前。本文回答一个问题：怎么从"市场已被验证的结构"里拿出"本书自己的东西"，而不把别人的书搬进来。

## 四轴结构拆解（只拆结构，不拆措辞）

对每本对标书只拆四轴，每轴有明确的引擎去向：

| 轴 | 拆什么 | 去向（引擎门） |
|---|---|---|
| 题材与读者承诺 | 类型、读者期待与基调：这本书向读者承诺什么爽点、多快兑现 | genre 门方向输入 |
| 脑洞形状 | 一条根规则 + 谁与谁博弈 + 兑现节奏：规则改变了谁的处境，压力从哪来，多久给一次回报 | premise/world 门 |
| 节奏与体量 | 章幅、卷结构、字数、月票/在读/书友数 | scale 门档位参考 |
| 兑现方式 | 早期兑现物与期限、阶段回报、终局回应的形状 | payoff 门参考 |

四轴之外的东西（人名、招式名、具体场面、台词）**不在拆解产出里**。

## 三条红线（逐条自查后才可立项）

- **红线一（专有名词不搬）**：对标书的人名、地名、组织名、功法/序列/称号体系名一律不进入候选与门方向输入。拆解记录的 red_line_check 逐条自查后才可立项。
- **红线二（桥段不搬）**：对标书的具体情节序列、名场面、台词不搬；只允许"该结构在本书世界里的等价压力测试"层面的形状借鉴（如"低资源方靠规则知识与大势力博弈"这一骨架）。落到具体场面必须由引擎门任务在本世界重新生成。
- **红线三（设定组合不整搬）**：同一组设定标签的整体移植即同质化。

自查清单（写入 teardowns 文件的 red_line_check，逐条打勾）：

- [ ] 候选与门方向输入中无对标专有名词（人名/地名/组织名/功法·序列·称号体系名）
- [ ] 无对标具体情节序列、名场面、台词
- [ ] 设定组合不是对标组合的原样移植（附差异增量声明佐证）
- [ ] 结构结论已用抽象语言重述，不含对标专有措辞
- [ ] 拆解记录带来源 URL 与抓取日期

## 抽象重述规则

拆解结论必须以**抽象结构语言**重述后，才可作为门方向输入；对标书的措辞不进任何门输入。重述的粒度：只保留"根规则—博弈结构—兑现节奏"这样的结构骨架，剥离一切专属名词与专属场面。

- 反例（不可用）："像《诡秘之主》那样主角扮演愚者先生在贝克兰德晋升序列。"
- 正例（可用）："低资源方持有一条别人不知道的规则知识，靠它与掌握暴力的大组织长期博弈，每次兑现都换来更大的暴露风险。"

重述后的文本存入 teardowns 文件的 abstractions 字段——这是唯一允许进入门方向输入的拆解产出。

## SETTING_CLICHES 告警与差异增量声明

引擎维护一份设定俗套词表 SETTING_CLICHES（contracts.py:121-122 本轮已核实）：**序列、途径、克苏鲁、克系、系统、幕后黑手、第四天灾、诸天、无限流、模拟器、签到、存档重开**——当前头部作品已经拥有的公共设定组合。拆解时逐本标注命中（teardowns 的 engine_cliche_hits 字段）。

告警性质：advisory 只警不拦——板面显示警告，作者保留选择（contracts.py:118-120，与主角门 name_warnings 同级）。总编的纪律：

1. 告警**原样转呈**用户，不自作主张毙掉方向；用户坚持则以作者为准。
2. 但立项提案必须附**差异增量声明**："对标组合已被市场拥有，本书在其上加什么新根规则"——说清楚新增的根规则改变了什么博弈，而不是换个皮。**无增量的候选不提出。**

## 原创性判断归引擎机制与作者，总编不另造文学判断

- 换组纪律要求新组与被拒组实质不同并吸收作者偏好（opening.md:53）；引擎的 opening_diversity 拒绝同组方案推进方式同构（opening.md:109）。
- opening.md:79 明言"机械通过不代表脑洞原创或文学质量达标"。
- 总编只做结构抽象与红线自查；"这个想法够不够原创/好不好"的取舍一律归用户。

## 来源留痕规则

- 所有对标拆解带来源 URL 与抓取日期（teardowns 文件的 book 字段）。
- 市场快照按月留档不改写（memory/market/YYYY-MM.md 一月一档）。
- 目的：防止"记忆里的市场"漂移成想象——每条结论都能回溯到某天某页的真实数据。

## 代理指标边界

- **市场数据是选题信号不是创作目标**：月票/在读/字数/书友数用于选题与档位参考，不写入正文目标（写什么不由榜单数字决定）。
- **机械通过不等于文学认可**：引擎文风代理指标通过不能证明文学质量（novel-ledger SKILL.md:39"不将机械通过说成文学认可"；README:17；narrative.md:186"数值约束仍不能证明文学成立"）。
- 总编不得把任何代理指标（榜单排名、字数、机械校验通过、文风数值）说成质量结论；阅读效果需人工抽读或离线盲测（README:17）。
