# 流程 A：市场扫描

进入条件：用户要求"扫一下双榜 / 看看市场"；或拟用于立项的观察已超过一个月/不属当月。新格式的时效取 `observations[].at`，旧格式取 `scan_date`；写入日期、文件名或 created_at 不刷新旧市场数据。

前置：`environment.md` 已解析路径。档位：全程只读采集，属 `policy.md` §2 的 T1（不产生作者决定）。写快照前读 `references/editorial-judgment.md` 的市场证据规则与 `memory/templates.md` §1。

## 先定义可比队列

按平台、商业模式、受众、作品阶段、指标名称/单位/分母和观察窗口划分队列，再看数字。至少尝试覆盖头部、上升、普通与掉队样本；取不到的组明确写缺失原因，不只从成功书推出市场规律。每条数字附原始来源身份、观察时间、已知曝光干扰；转载与同一数据的多页展示不算独立源。

事实、推断、待验证假设分开记。单期榜面是观察，趋势需要同队列跨时间证据；跨平台不可比的数字并列展示，不直接排高低。缺分母、曝光不可知或样本不足时收窄结论，不能补出“市场正在转向”的确定断言。

## 扫描序列

- **A1 付费盘月票榜**（第一手，免登录）：抓 `https://m.qidian.com/rank/yuepiao/` → 记 Top20 书名/作者/分类/月票数（当月口径）。
- **A2 付费盘畅销榜并置**：抓 `https://m.qidian.com/rank/hotsales/` → Top20 含字数。双榜同在是值得复核的商业信号，不能单凭重合宣布最强方向或证明作品价值；字数只作体量代理。
- **A3 详情页补数**：从榜单页**抄** `/book/<书ID>/` 链接（书 ID 自造必 404）→ 取简介/标签/书友数（体量第二代理）。
- **A4 分类榜与历史月**（需要时）：起点桌面版对内建抓取返回空 → 用渲染式 webReader 抓 `https://www.qidian.com/rank/yuepiao/chn<NN>`（玄幻 21 / 仙侠 22 / 都市 4 …）；侧栏各分类在库总数 = 拥挤度分母；该页默认展示上一完整月归档。**数字仍回移动版取**（桌面版月票是字形混淆字体）。
- **A5 免费盘口径确认**：抓 `https://fanqienovel.com/rank` → 默认分类榜 + 当次榜单规则，记录字数/签约/更新/在读门槛及验证期、推荐阶段；旧快照中的规则是历史口径，不自动套到本次。
- **A6 免费盘分类采样**（至少四类）：`/rank/1_2_1014`（都市高武）、`/rank/1_2_261`（都市日常）、`/rank/1_2_257`（玄幻脑洞）、`/rank/1_2_539`（悬疑脑洞）；新书层把第二段换成 1：`/rank/1_1_262`（都市脑洞新书榜）。记在读数 + 简介脑洞标签；男频分类 ID 全枚举见最新快照 `sources`；女频 ID 未枚举，需要时从 `/rank` 导航页取链接。
- **A7 番茄详情页补数**：从榜单页**抄** `/page/<书ID>` → 简介全文/字数/标签/章节进度；顺带修复榜单页乱码书名。**在读人数只在榜单页**，两页配合。
- **A8 交叉核对**：官方规则与行业报告核对适用时期，第三方盘点只提供线索；记录实际原始 `origin_id`，不是数 URL。市场范围的确定结论须有可比材料与独立来源支持；同源转载不算双源，单源观察和待验假设仍可保存，但不得伪装为已证实趋势。
- **A9 写快照**：按 `memory/templates.md` §1 骨架新建 `$CHIEF_EDITOR_MEMORY/market/YYYY-MM-DD-HHMMSSffffff-<id>.md`，其中单一 JSON 证据块使用 `market_snapshot` 记录；先运行 `scripts/check_editorial_evidence.py` 核验实际记录，失败就修正断言/补证据，不降低判据。每次扫描独立一档；`id` 使用当次唯一标识，路径已存在就换新标识，不覆盖。同月复扫也保留全部旧档。

## 降级速查

| 坑 | 降级动作 |
|---|---|
| 桌面版返回空 | 渲染式 webReader，或全走 `m.qidian.com` |
| 月票数字乱码 | 一律回移动版取明文 |
| 移动版无分类榜 | 桌面版 webReader 只取分类与在库数 |
| 起点阅读指数榜 | 2023 陈旧快照，弃用 |
| 番茄巅峰榜无网页入口 | 第三方帖 + 机制报道交叉 |
| 知乎/百度百科 403、今日头条 JS 渲染取空 | 回避，换源 |

## 硬规则

- **起点付费盘数字走 `m.qidian.com`**；其他平台使用各自当次原始来源，不能混用指标。起点桌面版混淆数字的限制来自历史实测，执行时仍记录实际可读性与降级路径。
- 书 ID、分类 ID 只从榜单页链接抄，不手写。
- 快照里的每个数字都能回溯到某天某页；给不出的格填"未记录"，不估算（`memory/templates.md` 通用纪律）。
- 市场数据只是选题信号与档位参考，不是创作目标，也不是质量结论（`references/red-lines.md#7`）；商业适配判断、文本审美判断与作者偏好各自交付，不给综合总分。

## 记忆

新建 `$CHIEF_EDITOR_MEMORY/market/YYYY-MM-DD-HHMMSSffffff-<id>.md`：双榜原始数据、来源、方向观察、体量基准尺与限制。**旧档不改写**，对比增量写进新快照。

读取时间口径：新 JSON `market_snapshot` 用 `observations[].at` 中真实时点的最大值排序，无观察则没有可用观察日期；`created_at` 只表示编档，保存文件名只表示落盘。用于某一商业结论时，只取该 claim 的 `evidence_ids` 对应观察的最新时点判断当月/陈旧，不能让同档其他新观察给旧结论续期。旧版 Markdown 按 `scan_date` 读取，缺失就标未验证；不因旧文件名格式排除它，也不回写补造。新格式没有 scan_date 字段，不向 JSON 塞未定义字段。

## 出口

快照落盘 → 用户要拆解则进 `flows/teardown.md`；要立项则进 `flows/selection.md`。
