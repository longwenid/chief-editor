# 流程 B：对标拆解与原创边界

进入条件：立项提案前需要结构输入；或用户要求分析某书结构。结构拆解可以独立交付，不要求同时立项；书评与纯讨论不进入本流程。

前置：读 `references/editorial-judgment.md` 的文本比较规则；需要挑书时先读当月最新有效 `market` 快照，用户已点名则按其范围拆解，不强制附加市场扫描。档位：只读分析，属 `policy.md` §2 的 T1；拆解结论进候选前要过下面的红线自查。

## 1 选书

从最新快照取 2~4 本高置信头部书（双榜同在、跨平台同方向优先），每书一份 `$CHIEF_EDITOR_MEMORY/teardowns/<书名>.md`。

## 2 四轴结构（只拆结构，不拆措辞）

| 轴 | 拆什么 | 去向（引擎门） |
|---|---|---|
| 题材与读者承诺 | 类型、读者期待与基调：承诺什么爽点、多快兑现 | `genre` 门方向输入 |
| 脑洞形状 | 一条根规则 + 谁与谁博弈 + 兑现节奏：规则改变了谁的处境，压力从哪来，多久给一次回报 | `premise` / `world` 门 |
| 节奏与体量 | 章幅、卷结构、字数、月票/在读/书友数 | `scale` 门档位参考 |
| 兑现方式 | 早期兑现物与期限、阶段回报、终局回应的形状 | `payoff` 门参考 |

四轴只产出可迁移的结构，不把人名、招式名、具体场面或台词带进新书。仅凭简介和榜位不能填出未读部分的阅读效果；结构假设与实际细读结论分别标明。

## 2b 匿名成对细读与反例

按 `taste_comparison` 证据记录比较可取得的同类、同范围材料，不必从“有钩子/有升级/有反转”清单出发。材料不足就写 insufficient；类型、阶段或长度差异无法控制就判 incomparable。保留完整书目的来源映射，但匿名评审者只收到 A/B 文本、位置与比较范围，不收到作者名气、榜位和销量；交换顺序复评，分歧不能藏掉。

每个判断都写具体文本位置、叙事机制、造成的读者体验、成立的代价和适用边界；另留一条会削弱结论的反例。允许慢开篇、留白、复杂叙事等非模板方案因具体阅读效果胜出，不能因缺少某固定结构而自动淘汰。热度可揭盲后用于商业背景，不能反向充当审美理由，也不给综合总分。

公开对标只读本次范围内合法可取的材料，不收集或保存整部小说。已有引擎项目仍守主干不读正文的角色边界：使用引擎实际派工产生的审读/写作报告或作者反馈核验，不自造 Worker 阶段与读取权限；报告不足就保留未验证。新判断引用报告与引擎事实源，不抄成第二份小说事实账本。

比较记录放入对应拆解记忆的单一 JSON 证据块，来源映射不交给匿名评审者。先用 `scripts/check_editorial_evidence.py` 校验记录结构与证据关系；通过不等于审美正确。

## 3 三条红线（逐条自查后才可进候选）

- **专有名词不搬**：对标书的人名、地名、组织名、功法/序列/称号体系名一律不进入候选与门方向输入。
- **桥段不搬**：具体情节序列、名场面、台词不搬；只允许"该结构在本书世界里的等价压力测试"层面的形状借鉴（如"低资源方靠规则知识与大势力博弈"这一骨架）。具体场面必须由引擎门任务在本世界重新生成。
- **设定组合不整搬**：同一组设定标签的整体移植即同质化。

自查清单（写进 teardowns 的 `red_line_check`，逐条打勾才可进候选）：

- [ ] 候选与门方向输入中无对标专有名词
- [ ] 无对标具体情节序列、名场面、台词
- [ ] 设定组合不是对标组合的原样移植（附差异增量声明佐证）
- [ ] 结构结论已用抽象语言重述，不含对标专有措辞
- [ ] 拆解记录带来源 URL 与抓取日期

## 4 抽象重述（唯一可进引擎的产物）

拆解结论必须以**抽象结构语言**重述后才能作为门方向输入，只保留"根规则—博弈结构—兑现节奏"骨架：

- 反例（不可用）："像《诡秘之主》那样主角扮演愚者先生在贝克兰德晋升序列。"
- 正例（可用）："低资源方持有一条别人不知道的规则知识，靠它与掌握暴力的大组织长期博弈，每次兑现都换来更大的暴露风险。"

重述文本存 `abstractions` 字段——这是唯一允许进入门方向输入的拆解产出。

## 5 SETTING_CLICHES 告警

引擎维护俗套词表（`$NOVEL_LEDGER/scripts/novel_ledger/catalog.py#SETTING_CLICHES`）：序列、途径、克苏鲁、克系、系统、幕后黑手、第四天灾、诸天、无限流、模拟器、签到、存档重开。拆解时逐本标注命中（`engine_cliche_hits`）。

告警是 advisory——只警不拦，板面显示警告，作者保留选择。总编的纪律：

1. 告警**原样转呈**用户，不自作主张毙掉方向；用户坚持则以作者为准。
2. 立项提案必须附**差异增量声明**："对标组合已被市场拥有，本书在其上加什么新根规则"——说清新增的根规则改变了什么博弈，而不是换个皮。**无增量的候选不提出。**

## 6 判断权归属

结构抽象、带证据的审美主见与红线自查是总编的活；说明为什么偏好一个方案、有什么代价及何时会改主意。执行取舍仍遵循亲选/委托/未授权三态，不能以总编品味覆盖作者明确偏好。`opening_diversity` 等机械检查只提供有限否证，不证明跨组新颖、脑洞原创或文学质量（`references/red-lines.md#7`）。

## 7 来源留痕

- 每份拆解带来源 URL 与抓取日期（`book` 字段）。
- 市场快照每次扫描独立留档，不改写旧记录。
- 目的：防止"记忆里的市场"漂移成想象——每条结论都能回溯到某天某页的真实数据。

## 记忆

写 `$CHIEF_EDITOR_MEMORY/teardowns/<书名>.md`，骨架见 `memory/templates.md` §2：`book` / `structure`（四轴）/ `engine_cliche_hits` / `abstractions` / `red_line_check` / `reuse_verdict`。

## 出口

用户只要结构分析时交付拆解并结束；需要立项且已有该项授权时 → `flows/selection.md` 生成候选。
