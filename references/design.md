# 设计与验收条件（2026-10-22）

本次范围是 chief-editor 的编辑判断与执行治理；沿用已有模块和用户工作区，不修改 novel-ledger、不建立第二份小说事实源。设计先于增强实现记录，验证结果由实际命令与独立评审另行报告。

## 设计

1. **入口保持短**：SKILL.md 路由；policy 管作者决定权；engine-cli 与 environment 管真实接口；阶段流程按需读取。
2. **判断有证据**：新增 editorial-judgment 作为编辑判断规范。市场证据、商业适配、作品价值、作者已表达偏好各自呈现，不合成总分。市场材料保存来源、可比队列、反例与观察限制。
3. **审美进入文本**：同类、同范围的匿名成对细读，换序复评，说明机制、体验、代价和适用边界。允许不可比、证据不足及不合模板的好作品；不能以热度、模板合规或机械通过证明作品价值。
4. **预测可被推翻**：立项预登记可反证判断和复核时机；复盘区分判断错误、执行偏离、曝光变化和观察不足。无真实读者数据时不宣称商业成功。
5. **总编能提出要求**：对当前板面说明拒绝原因、保留项和新约束，通过真实 regroup/门任务回执闭环；自拟候选仍先核验、展示、绑定版本再选择。scale、已确认方向、正文裁决各守真实接口边界。
6. **治理可靠恢复**：先 status，按 stage、真实 Worker 和 owner 恢复；正文授权前设计任务使用宿主事件；部分交付保持 active；同月扫描各建不可变记录。
7. **最终版本可审计**：真实执行检查，完整候选文件和 HEAD diff 同时绑定快照；评审后发生变化就使旧批准失效；发布产物失败不能偷偷修源并沿用批准。

## 验收条件

| 场景 | 必须满足 |
|---|---|
| 恢复、租约和设计阶段 | 只读查询不推进；有效 owner 不丢；活跃/未知 Worker 不重派；opening_options 自执；无 owner 设计等待不调用 watch |
| 部分交付 | target_reached 与 T2 保持 active；完本复验和正式交付均成功才 delivered |
| 自定义需求 | 全不满意、部分保留、自拟方案都能表达；仅输出真实 CLI；缺授权或改变已确认范围先交作者；有限换组后停下 |
| 市场证据 | 无证据趋势断言、同源伪交叉、不可比样本混比能够被拒绝；缺失样本与曝光干扰明确记录 |
| 作品价值 | 非模板佳作允许成立；判断有材料位置与机制；名气、热度和总分不能代替阅读证据 |
| 作者偏好 | 仅使用已表达原话；缺失时明确未知，商业主见不覆盖作者方向 |
| 复盘 | 使用事前预测，不能事后改写；无读者数据的商业结果未验证；长篇兑现引用引擎已有事实源或 Worker 报告 |
| 静态检查 | 命令真实档位覆盖、精确锚点、必填 CLI 参数通过；原假通过反例能失败 |
| 最终版本 | 评审后修改、检查失败、HEAD 变化、产物阶段漂移都闭锁；完整 diff 包括新增和删除文件 |

## 验证边界

标准库与 Node mock 测试验证确定性逻辑及工作流控制，不替代真实 DWF 宿主。独立模型情境评测检验 Skill 的判断路径，不证明文学质量；真实 Worker 隔离、租约长跑和平台商业表现需要另行端到端观察。本轮不运行真实写作、发布或市场实验。
